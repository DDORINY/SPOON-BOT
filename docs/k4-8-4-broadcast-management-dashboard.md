# K4.8.4 방송 관리 대시보드 B안

## 화면 구성

기존 단일 활성 탭 방식에서 후원·하트/자동화/청취자·팬 요약을 동시에 표시하는 세 카드로 전환한다. 기존 고정 사이드바 및 모바일 메뉴를 유지하고 중앙 채팅과 오른쪽 관리 영역은 약 2:1로 배치한다. 상단 통계는 단일 상태 바 안의 레이블/숫자 쌍으로 표시하며 좁은 화면에서 줄바꿈한다. 실제 후원 회차 귀속이 미확정이므로 현재 방송 합계는 계속 ‘—’, 시뮬레이터의 저장 합계는 ‘가상’으로 표시한다.

## 중앙 채팅 및 수동 전송

기존 채팅 목록·메모리 100건/5분·과거 스크롤 유지·새 메시지 알림을 재사용한다. 기본 연결 상태 설명을 짧게 하고 보조 안내를 상세 보기로 이동한다. 수동 전송 동의 체크박스와 봇 계정/방송 입장 안내, 전송 준비/UTF-16 제한/쿨다운/실패·불확실 처리는 유지한다. 반복되는 폼 밖 소개 문구는 기존 안내 상세에 넣는다. 입력 섹션은 자연 높이이며 메시지 목록만 제한 높이로 스크롤한다.

## 오른쪽 세 카드

후원·하트: 최근 저장 이벤트 최대 3건을 익명 또는 가상 표시로 요약하며 관측 하트 수량/이벤트 건수를 구분한다. 현재 방송 전체 합계라는 의미가 아님을 짧게 명시하고 내역 링크 및 원래 상세 목록을 유지한다.

자동화: 기존 ON/OFF 상태·대기열·최근 처리 결과를 항상 표시한다. 설정/템플릿·미리보기·간격/중지/Mock 기록은 접어 표시한다. 실제 모드는 기존 사용 불가 안내만 표시하고 조작 경로가 없다.

청취자·팬: 방송 조회에서 검증된 현재 청취자 수를 요약한다. 기존 수동 팬 조회가 완료되면 상위 3개를 요약한다. 미조회/빈 결과/오류는 상태 안내로 표시하며 데이터나 순위를 만들지 않는다. 상세 청취자/팬 내부 탭 및 수동 새로고침을 보존한다. 방송 대기·권한 오류 등으로 전환되면 팬 요약을 확인 필요로 처리해 이전 방송 순위를 현재 정보처럼 표시하지 않는다.

## 시간·설명

공통 ui-time.js가 Asia/Seoul 기준 오늘 HH:mm/어제 HH:mm/월 일 HH:mm을 제공한다. 후원 발생 시각과 수신 시각은 별도로 표기하며 원본 데이터는 변경하지 않는다. 잘못된 시각은 ‘시각 확인 불가’다. 채팅 수신 시간은 서울 HH:mm으로 짧게 표시한다. 기술 설명과 원본 JSON은 상세 보기로 두고 동의·오류·데이터 한계는 숨기지 않는다.

## 스크롤·반응형·접근성

오른쪽 관리 영역에 한 개 스크롤을 우선 사용하고 상세 목록의 중첩 스크롤을 줄인다. 카드가 차지하는 실제 높이를 grid가 따라가는 K4.8.3 정책을 유지하므로 안내와 도구가 자연 흐름에서 분리된다. 작은 viewport/확대에서는 페이지 스크롤 폴백을 허용한다. <=1100px은 채팅 우선 한 열, 모바일은 카드 세로 배열·터치 버튼·메뉴를 유지한다. 글자 크기와 포커스, 기존 폼 레이블을 유지한다. 새 상세 요소는 toggle 시 aria-expanded 상태를 갱신한다.

## 도구·초기화·보존

시뮬레이터 테스트 도구는 시뮬레이터 서버의 `/broadcast`에만 주입되고 기본 접힘이다. 다른 경로는 안전 배너만 남는다. 실제 미리보기는 준비 중 보조 영역으로 유지하고 영상을 만들지 않는다. studio.js가 DOMContentLoaded 이후 배치를 한 번만 수행하며 기존 요소를 이동하고 ID를 복제하지 않는다. simulator/automation 스크립트의 경쟁 배치 차단을 유지한다.

UI에 필요한 후원·팬 데이터를 기존 렌더러의 로컬 이벤트로 전달한다. 새 외부 API·폴링·자동 연결을 만들지 않는다. OAuth/SSE/DB·익명화·수동 전송·자동화 엔진·API 계약/보안 정책을 변경하지 않는다. 실제 API/토큰 발급/SSE/채팅/운영 DB 접근을 수행하지 않는다. 기존 브랜치·미커밋 변경·.env.example을 보존하며 커밋/push하지 않는다.
