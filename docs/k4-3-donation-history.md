# K4.3 후원 내역 검색·페이지네이션·통계

## 데이터와 범위

기존 donations의 record_id, received_sequence, amount_spoons_text, occurred_at_utc, received_at_utc를 사용한다. 저장 금액은 검증한 Decimal 스푼 수량이며 원화로 환산하지 않는다. unique(integration_key,stream_event_id) 중복 방지와 HMAC 충돌 기록을 변경하지 않는다. ID 없는 이벤트는 임의 중복 제거하지 않는다. nickname/message/user.id는 저장하지 않으므로 익명 청취자로 표시하고 고유 청취자 수는 계산하지 않는다.

기존 session_key는 수집 세션이고, K4.2 broadcast_round_id는 선택적 회차 참조다. 이번 조회는 계정·회차로 필터링하거나 집계하지 않는다. 기존 DB의 모든 소유 구역을 포함하는 로컬 기록 조회이며 단일 DJ 전용 운영을 전제로 한다. 회차 미확정과 신원 미확정 정책 자체는 유지한다.

## 조회 계약

GET /api/donation-history

- period: all(기본), today, 7d, 30d, custom.
- custom은 start/end YYYY-MM-DD 둘 다 필요하며 종료일을 포함한다. 다른 period에 start/end를 붙이면 400.
- Asia/Seoul의 날짜 자정을 UTC로 변환하여 시작 포함/끝 제외로 조회한다. 오늘/7일/30일은 오늘 포함 달력 날짜다.
- 발생 시각을 우선하며 없는 경우 수신 시각을 사용하고 각 항목의 time_basis와 UI에 구분한다. 현재 공식 파서는 발생 시각을 필수 검증한다.
- page 1~10000, page_size 12 또는 24. LIMIT/OFFSET은 서버에서만 적용한다.
- 최초 조회의 max received_sequence를 snapshot으로 반환한다. 이후 같은 snapshot을 전달하면 뒤늦게 들어오는 기록 때문에 과거 페이지가 밀리지 않는다. 새로고침/새 검색은 새 snapshot을 만든다.
- 발생/대체 수신 시각 DESC, received_sequence DESC로 동일 시각 정렬을 안정화한다.
- items, total, page, page_size, pages, has_previous, has_next, snapshot, statistics, timezone, time_basis, coverage, unit을 반환한다.
- statistics: 선택 기간 이벤트 수·Decimal 스푼 합계·오늘 이벤트 수·선택 기간 최근 시각. 오늘 수와 모든 통계는 동일 snapshot 기준이며 전체 방송 후원량을 의미하지 않는다.
- 잘못된 범위/페이지/중복 파라미터/알 수 없는 파라미터는 400, 로그인 없음 401, 접근 확인 필요 403, 저장소 오류 503이다.

SQLite mode=ro, query_only와 단일 읽기 트랜잭션을 사용한다. Decimal 집계 함수를 등록해 부동소수점 합산을 피하고 브라우저에 전체 레코드를 보내지 않는다. DB 생성/마이그레이션/인덱스 추가는 하지 않는다. 대규모 DB의 날짜 정렬 성능을 위한 인덱스는 향후 승인된 마이그레이션에서 검토해야 한다.

## 신원 미확인과 접근 제한

OAuth 로그인은 로컬 기존 기록 소유자의 신원 증명이 아니다. 다른 DJ가 로그인하면 기록이 노출될 수 있으므로 인증만으로 실제 저장 기록을 반환하지 않는다.

POST /auth/spoon/history/allow에서 기존 CSRF·Origin·Host·브라우저 세션 검사를 재사용한다. local_owner=confirmed라는 사용자의 명시적인 로컬 데이터 접근 권한 확인이 필요하다. 토큰·공식 DJ 신원·과거 회차를 추정하지 않는다. 허용은 현재 브라우저 세션 객체에만 결합하고 최대 15분 만료다. 서버 재시작/로그아웃/재로그인/세션 재발급 뒤에는 다시 확인해야 한다. 토큰 refresh 자체는 DJ 식별에 사용하지 않는다.

이 절차는 로컬 데이터 열람 의사 확인이며 실제 DJ 계정 격리의 보장이 아니다. 다른 DJ와 DB를 공유하면 안 된다. 운영자는 권한 없는 사용자에게 이 로컬 서버·PC를 제공하지 않아야 한다. 승인된 기록 접근 경계가 필요한 다중 사용자 서비스로 확대하지 않는다.

기존 /api/donations에서도 저장된 v1 기록은 확인 전 403을 반환한다. 미생성/비활성 저장소의 기존 빈 응답과 v2의 신원 미확인 빈 응답은 유지한다. 확인 뒤에는 기존 로컬 기록 계약으로 조회할 수 있다. 계정별 회차 API의 신원 확인 요구를 해제하지 않는다.

## UI

/donations에 기간 선택, 12/24개 선택, 통계, 익명 목록, 이전/다음, 새로고침, 빈 상태와 오류 안내를 추가했다. 접근 확인 전 모두 비활성이다. 외부 라이브러리 없이 로컬 history.js를 사용하고 textContent로 표시한다. CSP를 완화하지 않았다.

후원 내역 페이지는 기존 3초 후원 폴링에서 제외한다. 사용자가 조회/페이지 이동/새로고침할 때만 검색 API를 호출한다. 도우미 상태 폴링은 그대로다. 따라서 과거 페이지가 자동 변경되거나 새 이벤트를 조회 완료로 오인하지 않는다. 대시보드 최근 후원은 기존 갱신을 유지하되 접근 확인 필요 상태를 연결 오류로 오인하지 않는다.

## 검증 및 수동 확인

자동 테스트는 외부 소켓을 차단한 가상 OAuth와 임시 SQLite만 사용한다. 날짜 경계·Decimal·순번 snapshot·중복·빈 응답·입력 거부·접근 확인·CSRF/Origin/Host·다른 브라우저·만료·재로그인과 DB 바이트 보존을 검증한다. Node DOM 검사에서 텍스트 렌더링과 페이지 동작을 확인한다. 실제 Chrome 레이아웃/콘솔은 수동 검증 대상으로 남긴다.

Chrome: http://localhost:8000/donations에서 로컬 기록 접근 확인 → 오늘/7일/30일/사용자 지정 → 12/24개 → 이전/다음 → 새로고침을 확인한다. 오류·Tab 포커스·좁은 화면·수신 시각 표시·권한 만료·다른 브라우저 차단을 점검한다. 이 작업은 실제 OAuth/SSE/API를 자동 실행하지 않는다.

K4.4 제안: 접근 확인 UX와 운영 권한 정책 확정, 큰 DB 성능 측정 및 승인 기반 인덱스, CSV 내보내기의 별도 접근 제한·수식 주입 방어. 공식 DJ 식별과 회차 귀속은 별도 검증 단계다.
