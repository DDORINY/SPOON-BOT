# K4.7 시뮬레이터 방송 도우미 자동화

## 실행과 UI

`.venv/bin/python -m spoon_local --simulator` 실행 후 `http://localhost:8000/broadcast`에서 방송을 시작하고 자동화 설정을 명시적으로 적용한다. 감사/안내는 기본 OFF다. 설정은 메모리에만 있으며 종료·전체 시뮬레이터 초기화로 사라진다. 실제 모드에는 자동화 API나 패널을 등록하지 않는다.

## 구조 및 격리

`simulator_automation.Automation`은 제한된 큐와 실행 기록을 가진 동기 상태 엔진이다. 전송 결과는 내부 Mock 처리로만 생성한다. 실제 HTTP 클라이언트·OAuth 토큰·전송 어댑터를 주입할 인터페이스가 없다. 시뮬레이터의 기존 후원 정규화 및 메모리 SQLite 중복 판정을 통과한 이벤트를 연결한다. 정상 모드 코드를 변경하지 않는다. 기존 외부 소켓 차단·세션·Host·Origin·CSRF·CSP를 유지한다. 설정 API는 `/api/simulator/automation` GET/POST이며 POST는 기존 폼 검증을 사용한다.

## 후원 감사와 템플릿

검증된 양수 Decimal 스푼 수량만 사용한다. 기존 익명 저장 정책을 따라 `{spoons}`만 허용하며 nickname은 제공하지 않는다. 포맷 옵션, 변환, 속성 접근, 미확인 변수는 거부한다. 공백 및 UTF-16 200단위 초과 메시지를 거부하며 이모지는 2단위로 센다. 실제 수량 치환 후에도 재검증한다. 문자열은 HTML이 아닌 텍스트로 렌더링한다.

명시 ID는 세션 엔진 내 최대 5,000개까지 기억한다. 한도 이후 신규 ID는 제외한다. ID 없는 이벤트는 임의 중복 제거하지 않으며 완전한 중복 방지를 보장하지 않는다. 동일 ID 중복 감사는 차단한다. 기본 감사 쿨다운 10초, 설정 범위 10–3,600초이며 연속 이벤트는 쿨다운 제외로 기록한다.

## 안내·대기열·중지

기본 안내 간격 900초, 설정 범위 60–86,400초다. 첫 안내는 ON 또는 연결 복구 이후 설정 간격이 지난 뒤 생성한다. 큰 시간 점프에서도 지난 모든 회차를 따라잡지 않고 한 번만 생성하며 다음 예정 시각을 다시 잡는다.

큐는 최대 20건, 가득 차면 신규 메시지를 제외한다. Mock 시도 사이 간격은 최소 3초이고 기존 수동 Mock 전송과도 간격을 공유한다. 60초 넘게 대기한 메시지는 폐기한다. 자동화 OFF는 관련 큐 취소, 전체 중지는 모든 설정 OFF와 큐 취소다. 방송 종료·변경·연결 끊김은 큐를 취소한다. 재연결 시 과거 큐를 전송하지 않는다. 시나리오 중지 버튼은 자동화도 중지한다. 서버 종료는 작업을 취소하고 메모리 리소스를 닫는다. 로컬 브라우저 세션 만료 시 자동화를 중지한다.

전송 실패/타임아웃/불확실은 서로 구분해 기록하며 해당 메시지를 자동 재전송하지 않는다. 오류 주입은 기존 시나리오 A–D와 수동 오류 버튼을 사용한다. 자동화 결과는 시나리오 생성·처리 결과와 별도로 표시한다.

이 수치는 DOHA-BOT 로컬 보호 정책이며 SPOON 공식 API 제한이라는 의미가 아니다.

## 시간과 기록

주입 가능한 단조 시계에 가상 offset을 더한다. UI의 가상 시간 +15분은 시뮬레이터 자동화 시계만 진행시키며 실제 OAuth 만료나 운영 상태를 변경하지 않는다. 단일 명령 최대 86,400초다. 주기 작업은 0.25초마다 한 건 이하 처리한다. 기록은 최대 200건이고 종류·가상 단조 시각·상태·Mock 여부·사유 및 메시지를 메모리에만 보관한다. 메시지 원문을 SQLite나 로그에 영구 저장하지 않는다.

## 검증 및 한계

Python/Node 테스트로 익명 감사, 잘못된 수량, 템플릿/이모지 제한, 쿨다운, 큐 상한, 지연 안내, 큰 시간 점프, 중지/종료/재연결, Mock 실패·불확실, CSRF·세션 접근, XSS 안전 렌더링을 검증한다. 기존 OAuth/SSE/후원/수동 채팅 회귀 및 시뮬레이터 격리 테스트를 유지한다. 전체 테스트 454개 통과, JavaScript 문법 검사·pip check·git diff --check 통과. Chrome 실제 레이아웃 검증은 별도로 필요하다.

자동 생성 메시지는 Mock 기록이며 실제 SPOON 전송이나 수신 채팅을 의미하지 않는다. 영구 설정 저장·실제 자동 전송·방송 계정별 정책은 구현하지 않았다. 향후 실제 모드 연결에는 별도 사용자 승인, 공식 정책 검증, 권한 및 계정 격리, 동의·전송 보호 정책 설계가 필요하다. K4.8은 먼저 시나리오 A–D와 가상 시간·중지·재시작·모바일 레이아웃의 통합 검증을 권장한다.
