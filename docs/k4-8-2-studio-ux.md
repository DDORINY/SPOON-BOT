# K4.8.2 방송 스튜디오 가독성·UX

## 개선 전후

기존 화면은 작은 글자, 늘어진 오른쪽 카드와 여러 내부 스크롤, 입력 섹션 높이 제한으로 읽기와 조작이 어려웠다. 중앙 채팅을 우선하고 오른쪽을 후원/자동화/청취자 탭으로 구성한다. 기존 사이드바와 K4.8.1의 단일 레이아웃 소유권·DOMContentLoaded 배치를 유지한다.

## 상태 바와 가독성

헤더/시뮬레이션 배너/통계 여백을 줄이고 보조 페이지 설명은 시각적으로 생략한다. 시뮬레이션 경고는 그대로 표시한다. 방송/도우미 상태는 구분하며 기존 API에서 확인된 값만 사용한다. 실제 현재 방송 후원은 귀속 미확정이므로 ‘—’, 가상 후원은 가상 저장 합계다.

본문 15px, 채팅 16px, 닉네임 15px, 패널 제목 18px, 통계 18px, 보조 안내 12–13px 이상으로 구성한다. 긴 텍스트를 줄바꿈하고 색상만으로 상태를 전달하지 않는다.

## 채팅과 입력

기존 채팅 노드와 전송 폼을 이동하여 핸들러/동의/검증을 보존한다. 연결·수신 보조 설명과 링크는 ‘자세히 보기’에 모은다. 전송 체크박스·봇 계정 안내·오류/불확실 상태는 제거하지 않는다.

입력 섹션의 40% 높이 제한 및 별도 overflow 스크롤을 제거한다. 채팅 목록이 남은 공간을 사용하고 입력은 축소되지 않는 하단 섹션이다. 최소 작업 높이 560px를 확보하며 낮은 viewport/확대에서는 페이지 스크롤로 안전하게 접근하도록 한다. 입력을 감추는 overflow hidden 정책을 추가하지 않는다. 실제 viewport 내 입력 위치는 Chrome 검증이 필요하다.

## 오른쪽 탭

기본 후원 탭: 기존 최근 기록/관측 하트/건수 미확정 안내 및 내역 링크.
자동화 탭: 기존 시뮬레이터 ON/OFF 상태, 설정 폼·미리보기·중지·대기열과 접이식 Mock 기록. 실제 모드에서는 사용 불가 안내만 표시한다.
청취자 탭: 기존 현재 청취자/이번 방송 팬 랭킹 내부 탭, 수동 새로고침, 오류/로딩/빈 상태.

ARIA tablist/tab/tabpanel, aria-selected/controls/labelledby와 roving tabindex를 적용한다. 좌우/Home/End 키로 이동하며 선택 탭을 유지한다. 탭 전환은 hidden 속성만 변경하여 데이터나 자동화 실행 상태를 초기화하지 않는다. 기존 DOM을 다시 생성하거나 핸들러를 재등록하지 않는다.

자동화 탭이 숨겨지면 UI 상태 조회만 잠시 건너뛴다. 엔진 실행은 계속되며 탭을 열면 기존 주기 조회에서 최신 상태가 표시된다. 실제 청취자 조회는 계속 수동이다. 채팅과 방송 관측 조회는 방송 모니터링을 위해 유지한다.

## 스크롤·반응형

데스크톱 >1100px에서 중앙/오른쪽 약 2:1, 채팅 목록 및 오른쪽 활성 탭이 독립 스크롤이다. 오른쪽 후원/청취자 목록의 중첩 스크롤 제한을 완화하여 활성 탭 스크롤을 우선한다. 설정/접힌 기록은 필요할 때만 연다.
태블릿은 채팅 우선 한 열 + 탭, 모바일은 기존 메뉴 및 터치 버튼을 유지한다. 모바일 입력은 자연스러운 높이로 표시하고 목록 높이만 제한한다. 시뮬레이터 제어·가상 시간·시나리오/JSON은 기본 접힌 도구로 유지한다. Mock 기록은 자동화 탭으로 옮기고 도구에 위치를 안내한다.

## 검증과 제한

기존 OAuth/API/SSE/DB/익명화/채팅 100건·5분/수동 전송/자동화 엔진 정책은 변경하지 않는다. 실제 네트워크/OAuth/SSE/채팅/운영 DB 접근을 실행하지 않는다. CSRF/Host/Origin/CSP 및 시뮬레이터 격리를 유지한다. 브랜치·미커밋 변경·.env.example을 보존하고 커밋/push하지 않는다.

Node DOM 테스트에서 실제/가상 기본 후원 탭, 탭 클릭·키보드·ARIA/숨김, 기존 노드 보존, 레이아웃 초기화 순서 및 경쟁 배치 방지를 검증한다. 기존 Python·Node 전체 회귀와 JavaScript 문법/pip check/git diff --check를 실행한다.

Chrome 실제 렌더링은 미검증이다. 1920×1080,1666×895,1600×900,1366×768,1280×720,1024×768,390×844 및 확대 125/150%에서 입력 viewport 위치, body 높이, 목록 스크롤과 가로 overflow를 수동 확인해야 한다. ‘닫기’는 앱 소스에서 발견되지 않았으며 외부 주입/확장 여부도 확정하지 못해 임의 삭제하지 않는다.

수동 확인: `.venv/bin/python -m spoon_local --simulator` → `http://localhost:8000/broadcast` → 탭/키보드 이동 → 도구에서 방송 시작/이벤트/종료 → 자동화 설정/기록 확인. 실제 SPOON 테스트 없이 진행한다.
