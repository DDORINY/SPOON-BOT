# DOHA-BOT 스튜디오 — 1단계 UI 골격

구현 범위는 화면과 기존 기능 연결뿐이다. 신규 캡처 API·Windows 에이전트·SQLite migration·파일 저장/조회/권한 요청은 구현하지 않았다. 실제 .env와 운영 DB를 열지 않으며 사용자 .env.example 변경을 보존한다.

## 페이지와 실제 동작

| 경로 | 내용 | 기능 범위 |
|---|---|---|
| / | 방송 상태·연결·미리보기·오늘 캡처 수·바로가기·최근 후원 | 기존 명시 연결/중지, 관측된 후원 조회만 동작 |
| /broadcast | Windows 창/화면 선택·16:9 미리보기·갱신/중지·영역 설정 | 준비 중; 컨트롤 비활성 |
| /capture | 수동/후원 자동 캡처·PNG/JPG/WEBP·저장 설정 | 준비 중; 컨트롤 비활성 |
| /gallery | 오늘/7일/30일/직접 지정·12/24개·상세·다운로드 | 준비 중; 필터/페이지/다운로드 비활성, 임의 이미지 없음 |
| /donations | 기존 실제 관측 후원 최대20건·날짜 필터 UI | 조회만 동작; 날짜 검색과 관련 캡처 연결 비활성 |
| /settings | 계정/방송 연결 관리 | 기존 로그인 브라우저의 관리·로그아웃 사용 |

오늘 캡처 수·집계는 —이며 미리보기/목록에 가짜 화면이나 기록을 만들지 않는다. 저장 폴더는 Windows 연결 후 확인 가능하다고 표시하며 실제 사용자명/폴더가 확인된 것으로 주장하지 않는다. sidebar는 데스크톱 고정, 작은 화면은 줄바꿈 메뉴다. 외부 CDN/폰트/스크립트, 자동 화면 공유·업로드는 없다.

Real 모드 새 페이지에도 기존 서버 로그인 브라우저 바인딩과 localhost Host·중복 쿠키 검사를 적용한다. OAuth/state/CSRF/Origin/토큰/SSE 로직과 API 응답 계약·DB 스키마는 유지한다. 캡처 파일 endpoint가 없어서 인증 전후 모두 파일을 제공하지 않는다. 미래 파일 접근 보안이 구현되었다고 주장하지 않는다. CSP의 기존 로컬 CSS/JS 허용 범위도 유지한다.

## 2단계 제안 — 미구현, 적용 전 별도 보고

소스상 현재 운영 schema_version 및 별도 Real/Mock 후원 ledger를 확인했다. 어느 것도 수정하지 않는다. 캡처 메타데이터의 저장소 선택·schema version/마커·백업·migration 계획부터 보고한 뒤 승인 범위에서 적용한다.

후보 메타데이터는 capture_id(UUID), created_at_utc, format, width/height, byte_size, 저장 루트 식별자와 상대 파일명, 선택적인 후원 record_id, 저장 상태/안전한 오류 코드다. 개인정보가 포함된 원본 화면·원문 메시지를 DB/로그에 넣지 않는다. UI에 실제 경로 노출 범위를 별도로 결정한다.

후보 API는 인증된 GET /api/captures?date_from=...&date_to=...&page=...&page_size=12 또는24이다. 사용자 시간대와 UTC 변환, 허용 크기/최대 페이지·정렬·조회 범위 및 반환 계약을 먼저 정한다. 날짜별 서버 필터와 페이지네이션을 구현하고 빈 목록/저장 오류/관련 후원 링크를 테스트한다. 다운로드/미리보기는 capture_id로만 조회하며 임의 경로 문자열을 허용하지 않는다. 인증·파일 소유/모드·저장 루트·실제 파일/형식·symlink/path traversal 검사가 필요하다. 이 API는 현재 존재하지 않는다.

Windows 기본 저장 경로 후보는 `C:\Users\<사용자명>\Pictures\DOHA-BOT\Captures`이다. 실제 사용자 및 Pictures 위치는 Windows 에이전트가 런타임에서 확인한다. 리디렉션된 Pictures/WSL mount 설정을 고려하며 /mnt/c 경로를 임의로 고정하지 않는다. 저장 루트 변경은 사용자 동의와 검증된 허용 루트로 제한하고, 쓰기 권한·날짜별 폴더·UUID 포함 파일명·원자적 저장을 검증한다. 임의 파일 읽기/쓰기 API를 만들지 않는다.

3단계에서 Windows↔WSL 통신·로컬 에이전트 인증·대상 선택·화면 권한·미리보기 크기/속도·최소 수집·저장 실패를 별도 설계한다. 화면 공유/실제 캡처는 별도 사용자 승인 전 실행하지 않는다.

## 검증 범위

가상 OAuth와 임시 DB만 사용한다. 6개 페이지 렌더링과 서버 초기 가시성·메뉴·비활성 컨트롤·인증/Host 거부·캡처 파일/API404·외부 소켓/화면 권한 요청 없음·기존 보안 회귀를 검증한다. 실제 Chrome 레이아웃/콘솔 및 실제 Windows 기능은 사용자 검토가 남아 있다.
