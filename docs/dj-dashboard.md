# DJ용 로그인·대시보드

로그인 준비 → 보안 검증된 시작 POST → 로컬 계속 화면의 사용자 클릭 → 공식 인증 → 성공한 콜백만 홈303 이동. 실패는 기존 결과 화면으로 이동한다. 계정이 연결된 같은 브라우저의 준비 페이지 재방문은 홈으로 안내한다.

홈/후원 내역/설정은 화이트·오렌지 화면을 공유한다. 실제 실행 모드에서 서버가 확인한 로그인 브라우저 세션과 메모리 토큰이 있어야 홈과 후원 조회를 사용할 수 있다. 토큰만 있는 다른 브라우저는 거절하며 준비 페이지가 기존 세션을 덮어쓰지도 않는다. localhost Host와 중복 쿠키 검사도 보호된 경로에 적용한다.

성공 후 세션 쿠키는 HttpOnly/SameSite=Lax인 브라우저 세션 쿠키로 루트 경로에서 사용한다. 이는 파일 토큰 저장이 아니다. 로그인 브라우저 연결은 같은 메모리 세션 식별자와 유효 토큰으로 확인한다. 기존 인증 폼의5분 CSRF/세션 및 pending state 만료는 유지하며, 이미 인증된 브라우저에서 홈/관리 화면을 열 때 필요하면 새 CSRF 폼 세션을 준비한다. 이전 폼은 무효화될 수 있으므로 새로고침 후 다시 제출한다. 로그인 전 쿠키는 기존5분 제한이다. 서버 종료·로그아웃·갱신 실패 시 메모리 인증이 사라진다.

방송 연결 기능은 --real-oauth --real-sse-db의 별도 경로를 설정한 모드에서만 제공한다. 홈의 POST 폼은 기존 수집 시작/중지 라우트와 CSRF를 사용하며, 시작은 DJ 고지 확인도 필요하다. 조회/페이지 진입만으로 접속하지 않는다. OAuth-only 실행에서는 방송 기능이 준비되지 않았다고 표시하고 연결 버튼은 제공하지 않는다. Mock 데이터는 DJ 화면에 표시하지 않는다.

오늘 받은 후원과 청취자 수는 —로 표시한다. 날짜/시간대별 집계가 없고 청취자 식별 정보도 기본 저장하지 않기 때문이다. 최근 내역은 현재 별도 Real DB에 저장된 관측 자료를 최대20건 표시하며 전체 방송 후원 이력이 아니다. 중복·충돌·ID 없음·누락 가능성 정책은 기존 저장소에서 유지한다. 화면에는 개인정보 원문·계정 식별자·기술 상태 코드 대신 익명 금액과 시각, 일반 안내만 표시한다.

CSP는 로컬 스타일/스크립트/읽기 요청만 허용하고 form-action self를 유지한다. 외부 라이브러리·폰트·inline script는 없다. 인증 화면의 공식 링크는 기존 서버 생성 URL과 사용자 클릭만 사용한다. CSRF/Origin/Host, state 바인딩·소비·코드 중복 차단·scope/rotation·revoke·SSE 고지는 유지한다.

실제 사용자 .env/운영 DB는 변경하지 않는다. 테스트는 가상 토큰·Mock HTTP Transport·임시 DB·소켓 차단으로 실행하며 실제 로그인/SSE 성공이나 Windows Chrome 렌더링을 검증했다고 주장하지 않는다. 최신 검증 결과는 작업 완료 보고를 따른다.
